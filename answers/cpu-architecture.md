# CPU 아키텍처의 종류(ARM, x86)와 각 특징

## 요약

CPU의 명령어 집합 구조(ISA)에 따라 크게 RISC와 CISC로 나뉜다.

- **ARM** → RISC(Reduced Instruction Set Computer) 방식
- **x86** → CISC(Complex Instruction Set Computer) 방식

## RISC vs CISC — 명령어의 차이

`A = B * C`를 계산하는 경우:

```asm
; CISC (x86)
MUL A, B, C   ; 한 줄로 메모리 읽기 + 연산 + 쓰기까지 다 처리
```

```asm
; RISC (ARM)
LOAD R1, B
LOAD R2, C
MUL  R3, R1, R2
STORE A, R3
```

CISC는 명령어 하나에 여러 단계(메모리 접근 + 연산)가 압축되어 있고, RISC는 명령어 하나가 한 가지 일만 한다.

## 왜 회로 복잡도가 다른가

CISC 명령어 하나를 처리하려면 내부적으로 여러 단계(주소 계산 → 메모리 읽기 대기 → 연산 → 메모리 쓰기)를 순서대로 조율해야 하는데, 이 조율을 담당하는 게 마이크로코드다. 마이크로코드 자체가 추가 회로(트랜지스터)를 필요로 하기 때문에, CISC 칩은 회로가 복잡해지고 전력도 더 소모한다.

RISC는 명령어가 레지스터끼리의 단순 연산 위주(load/store 구조)라 이런 조율 로직이 거의 필요 없어 회로가 단순하고, 그만큼 전력 효율이 좋다.

## "Reduced"의 의미

"명령어 집합을 축소했다"는 건 실행되는 명령어의 **개수**가 줄었다는 뜻이 아니라, CPU가 이해할 수 있는 명령어의 **종류**가 줄었다는 뜻이다. 오히려 같은 작업을 처리할 때 RISC는 CISC보다 더 많은 명령어를 실행해야 한다.

## CISC(x86)가 여전히 쓰이는 이유

- **코드 밀도** — 명령어 하나가 많은 일을 하므로 프로그램 크기가 작아진다. (메모리가 귀하던 시절엔 중요한 장점이었다)
- **레거시 호환성** — 수십 년간 쌓인 x86 기반 소프트웨어 생태계
- **내부적으로는 RISC처럼 동작함** — 1990년대 이후 x86 CPU는 CISC 명령어를 내부적으로 RISC 스타일의 micro-op으로 쪼개서 실행한다. 겉(ISA)은 CISC, 속(실행 엔진)은 RISC에 가까운 하이브리드 구조다.

## 오늘날 성능을 좌우하는 건 ISA가 아니라 하드웨어 구현

x86도 내부적으로 RISC처럼 동작한 지 오래됐기 때문에, 오늘날 CPU 성능을 가르는 건 RISC냐 CISC냐(ISA)가 아니라:

- 제조 공정 (몇 나노미터인지)
- 마이크로아키텍처 설계 (파이프라인 폭, 캐시, 분기 예측)
- 전력 예산 (모바일이냐 서버냐)

다. 전력이 절대적으로 중요한 모바일 환경에는 RISC(ARM)이 유리하고, 전력보다 성능·호환성이 중요한 데스크탑·서버 환경에는 CISC(x86)도 여전히 경쟁력이 있다.

## iOS 기기 / 시뮬레이터 아키텍처

- iOS 실기기는 ARM(arm64)을 사용한다. 모바일 기기는 배터리로 구동되기 때문에 전력 효율이 중요해서다.
- Intel Mac 시절엔 시뮬레이터가 x86_64로 실행되어 실기기(arm64)와 아키텍처가 달랐다.
- 지금은 Apple Silicon Mac이라 시뮬레이터도 arm64로 실행되어, 실기기와 아키텍처가 동일하다.
